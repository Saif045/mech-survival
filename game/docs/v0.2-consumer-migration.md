## Windows editor/import DLL contention

The first candidate import failed to copy/open GodotSteam's temporary debug DLL
while another editor was open on this checkout. With the editor closed, the
unchanged DLLs passed import (`task_f_dll_editor_closed_20261018_01`). No binary
rebuild, vendor change or Steam restart was needed. Godot's Windows loader uses
a fixed `~<library>.dll` copy for editor loading, so concurrent editors/imports
can contend for it. This explains the captured failure; it does not establish
the cause of separate reboot-time reports. Canonical game Import runners now
block during preflight if this checkout already has an editor open. Keep the
editor closed during import/export validation; a stale temporary file alone is
not proof of a bad source DLL. Preserve and diagnose errors before rebuilding.
