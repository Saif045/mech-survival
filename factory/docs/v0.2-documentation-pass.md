## Audit findings before edits

- No usable canonical subsystem guide existed for networking, Netfox glue,
  interaction, Steam, runtime roles or diagnostics. Important APIs required
  source reading or broad integration documents. Carry and shell had useful
  contracts; starter GAS needed a much stronger composition reference.
- Interaction composition appeared in gameplay routing, architecture and consumer
  workflow. Networking/Steam/Netfox usage appeared in broad docs; diagnostics had
  its detailed guide in docs/. These are now subsystem teaching locations with
  concise cross-cutting links rather than repeated API exposition.
- Carry and shell appended dated acceptance records to normal implementation
  reading. Consumer interaction included Task A run/failure history.
- Factory default context required current-state even for ordinary features;
  networking required architecture/module-map for normal contract work; Netfox
  and Steam routers required broad integration/history docs. Interaction went
  back up through gameplay and sideways through the consumer manual.
- Starter GAS routing described Netfox as frozen during an earlier phase. The
  consumer guide described runtime/starter separation as future work, placed
  factory/tests below game/, and introduced the current foundation as v0.1.
- Executable documentation examples still used root tools paths in six files.
  Captured artifacts and intentional old-to-new migration tables are not stale
  current paths and must retain their original content.

## Contract, starter and router results

The factory catalog gives problem, canonical guide and reusable/reference status
for every requested mechanism, without teaching their APIs. New guides provide
real composition/API examples, authority/identity/trust boundaries, extension
points, non-goals, mistakes and focused validation pointers. Runtime and
diagnostics gain short routers because their public contracts now have clear
teaching homes.

Starter README maps player, GAS, inventory, interaction, carry and shell and
explains the small reference-only semantics. The focused player guide covers
its scene/projections/initialization; GAS is expanded substantially. No six large
starter subsystem manuals were added.

Root AGENTS remains unchanged as the ownership router. Factory, gameplay,
networking, Netfox, interaction, Steam, starter and starter GAS routers were
shortened/refocused; carry, shell and A/B routers were reviewed and retained.
Factory is 44 lines; scoped routers range from 8 to 22 lines. Normal tasks no
longer require current-state, architecture or acceptance logs. Conditional
cross-boundary links do not form mandatory cycles.

GAS coverage includes GodotGAS/factory/starter/game ownership, canonical server
state, explicit ordinary projections and partial client mirrors, source-owned
effects, preservation of unrelated effects, AttributeSets/effects/tags/abilities,
all five resource settings, typed C#↔GDScript adapters, teardown/source lifetime,
and a game-authored composition pattern. GAS stays outside rollback; explicit
physical projections and consumed dash/respawn revisions define that boundary.
The guide explicitly forbids attaching starter NetworkGasComponent merely to
use GodotGAS and routes raw addon API work to vendored material.
