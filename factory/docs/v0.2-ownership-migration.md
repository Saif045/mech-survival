## Composition and local tooling

GameShell's public `OnlineGameplayScenePath` constant is replaced by exported
`FallbackGameplayScenePath`. The moved starter autoload scene explicitly sets it
to the moved default scene. Maaack's valid `game_scene_path` still wins for every
Host/Join/invite/command-line route; absent/invalid settings use the configured
fallback. A custom GameShell composition must supply a valid gameplay target or
fallback; missing both now reports a clear configuration error. This minimal
API change prevents reusable shell code from naming starter content.

Project settings explicitly set GodotGAS's attribute draft/output, cue registry,
tag registry and generated tag script paths. The addon supports these overrides;
no vendor modification or GAS semantic change is required. Consumers choosing
their own resources must reconcile all five settings and autoload composition.

Run helpers from `factory/tools/` and probes from `factory/sandbox/`. PowerShell
runners ascend to `project.godot` to find the repository; new evidence goes to
`factory/artifacts/`. Ignore rules and solution discovery use the new paths.
Local A/B endpoint/runtime configuration moves with the tools. Re-run
`factory/tools/ab_test/host/install_host_task.ps1` before the next interactive
A/B session to reconcile a previously installed task's absolute runner path.
Do not automatically restart Steam, reconfigure the VM or rewrite immutable
build manifests for this source migration.

Historical evidence keeps original embedded paths, source diffs, checksums and
export composition; its directory is relocated, its contents remain unchanged.
Vendor default `res://godot_gas` strings and this explicit old-to-new map are
intentional old-path mentions. Current first-party resource/tool references must
resolve at the new locations. Prior Steam/VM acceptance is historical evidence,
not a claim that this migration reran it.
